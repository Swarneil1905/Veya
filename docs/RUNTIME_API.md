# Platform and private runtime contracts

## Go application boundary

Both clients use the Go platform. The desktop host provisions a platform token over an inherited pipe; the web launcher provisions the same protocol and serves the Angular build on loopback. Go starts Python with a separate private token. Python owns the existing durable execution/storage invariants; no inference or external business effect runs on task submission.

`POST /api/workspace` accepts exactly `{operation, args}`. Supported operations are `list_tasks` (latest ten), `submit_task` (client_request_id/title/instruction), `recovery`, `latest_run` (task_id), and `events` (run_id/after). Unknown operations, extra arguments, invalid identifiers and cross-run cursors are rejected before contacting Python. The request limit is 128 KiB. Clients cannot supply a tenant, worker URL, reviewer identity or arbitrary execution operation. The current local workspace retains its `desktop` tenant identity and on-disk schema; cloud tenant provisioning is not implemented.

`GET /api/health` and desktop-compatible `GET /v1/health` return the private runtime's protocol health after authentication. Native calls use the platform Bearer token. The browser exchanges its launch fragment at `POST /api/session` for an HttpOnly SameSite=Strict cookie and removes the fragment. Cookie writes require the exact same Origin; all requests require the bound loopback Host. Cross-site requests and arbitrary proxy routes are rejected. Tokens rotate per process. Web workspaces persist their bound port in `platform-http-port` to retain the browser origin and local drafts across restarts; a busy/invalid saved port fails closed. No worker credential or upstream header is forwarded to the browser.

Closing the parent's stdin pipe requests bounded Go shutdown, which closes the worker's pipe and reaps it. Unexpected worker exit stops the platform. Native restart creates a new pair of credentials while preserving the storage root and request IDs. Go transport calls are bounded and do not follow redirects. Platform errors use `{error:{code}}`; private runtime errors carry the richer schema below.

## Private Python execution API

The following `/v1` routes are internal worker contracts, **not browser-accessible platform endpoints**. Tests and trusted runtime integrations can construct `create_app(settings, session_token)` explicitly. Adding a new user capability requires an explicit authorized Go command; the worker is not a general-purpose proxy.

All HTTP routes use `/v1`, a configured tenant, and `Authorization: Bearer <session_token>`. Tokens must have at least 32 characters; there is no default token. Browser Origin headers are rejected. Request bodies are limited to 1 MiB including chunked input. Errors have `{error: {code, message, schema_version, retryable}}`; input is never echoed. SQLite contention returns retryable 503; retry submissions using their original request ID.

## Tool declarations and proposals

Inject a trusted `ToolRegistry` and tenant-matching `ToolScope` into `create_app` to enable tools. The default scope is empty. `GET /v1/tools` returns only enabled declarations whose required capabilities are granted. Each declaration pins a semantic version, effect (`read_only`, `write`, `destructive`), strict Pydantic input/output schemas and explicit byte limits. Tool models inherit `ToolPayload`; unknown fields, coercion, invalid defaults, non-JSON values and oversized normalized payloads fail validation.

`POST /v1/runs/{id}/proposals` accepts `{tool_name, tool_version, arguments}` and returns a new immutable proposal with 201. It validates scoped arguments and binds canonical argument and complete declaration SHA-256 hashes. Terminal runs reject new proposals. `GET /v1/proposals/{id}` retrieves the original tenant-scoped review record. Returned arguments are detached copies. Creating another proposal always allocates a new ID; proposals and their events commit together, and SQL triggers prevent proposal edits/deletes. `ProposalStore.validate_current` rechecks grants and declaration identity before a future approval/execution boundary.

Planning does not grant approval or execute tools. There is no public tool-execution route or approval UI in this batch.

## Internal operation intents and retries

`IntentStore.execute(scope, operation_key, proposal_id, authorized_handler)` reserves a tenant-scoped key before dispatch. The key binds the proposal's run, canonical arguments and declaration. Equivalent proposals in the same run can replay; changed arguments, declarations or runs conflict. Keys use the existing 1–64 identifier-character contract. This internal API requires a handler already authorized by the caller; it does not implement user approval or validate external provider delivery.

A new reservation is durably `unresolved`. Concurrent duplicates return that state with no result and do not dispatch. After the original handler's validated result commits, repeating the call returns `succeeded` and the stored result. Handler exceptions, invalid results, process death, timeout or a failed completion transaction leave the reservation unresolved. There is no automatic expiry/reclaim or reconciliation endpoint. Treat unresolved as requiring reconciliation, never as permission to create a new key and repeat the effect. A durable fixture-effect crash test verifies local duplicate suppression; this is not an exactly-once guarantee for external providers.

`execute_async` has the same contract and moves database work off the event loop. Cancelling a claim wait may still leave a durable unresolved reservation, but never dispatches the handler. Cancelling a completion wait may still commit its already-known result.

`ToolRunner.run` accepts an async connector adapter and takes effect classification from the scoped registry. Configure `RetryPolicy(max_attempts, attempt_timeout, total_timeout, base_delay, max_delay)` explicitly: 1–10 attempts, positive finite timeouts, nonnegative finite delays bounded by one hour, and base delay no greater than max delay. Read-only transient failures and timeouts retry within both attempt and total budgets, using capped exponential backoff with full jitter. Authentication, permanent and unknown failures do not retry. Any write/destructive handler failure is conservatively an unknown outcome. Wrap write dispatch in the intent executor; the runner alone is not duplicate protection.

Adapters must be asynchronous and nonblocking; isolate blocking or untrusted work in a separate process. A timeout requests cancellation and returns without waiting indefinitely for an adapter that ignores cancellation. Late adapter completion does not resolve the intent. Cancellation cannot prove an external write stopped. Inputs are copied and validated for every attempt, and returned outputs must satisfy the declared schema and byte limit.

## Scoped execution gateway

`ToolExecutor` is the application boundary for invoking registered internal adapters. The trusted host injects a workspace ID, a provider of immutable `PolicyEngine` snapshots, and `ToolBinding` entries. A binding maps a declared tool/version to one operation, an authoritative resource resolver and an async handler. Requests provide an authenticated `Actor`, an existing `ToolScope`, an operation key and a proposal ID; they cannot supply a handler or permission grants through HTTP. No new authentication or public execution endpoint is introduced.

Policy grants match the actor, tenant, workspace, tool, operation, each required capability, each resource identity and its exact classification. Missing identity/resources, unknown capabilities/classifications and cross-scope references fail closed. Write/destructive grants additionally name the exact immutable proposal ID and require an unexpired signed approval receipt (see below). A scoped grant alone cannot dispatch a write. No built-in grant, wildcard access or approval UI is provided.

The gateway checks before reserving an intent, immediately before dispatch, and before returning a result (including replay). It resolves resources again after the dispatch-admission await and checks the current policy and approval expiry. Resource resolvers must be nonblocking synchronous reads of authoritative host metadata and enumerate every affected resource; connectors must honor those bindings. Policy version and grant IDs are recorded in an `action.authorized` event before dispatch. These checks cannot retract an external effect already underway after authorization.

Intent identity also binds the actor, workspace, operation, resolved resources and classifications. Reusing an operation key across these contexts conflicts, even when a tool name and arguments match. A permission change while a reservation is pending may leave it unresolved without dispatch. This conservatively prevents automatic redispatch; reconciliation remains future work. `IntentStore` and `ToolRunner` are lower-level primitives for trusted callers and do not replace this gateway's authorization checks.

## Untrusted tool result boundary

`ResultNormalizer.normalize` handles parsed JSON objects; `decode` handles strict UTF-8 JSON bytes; `read` collects an async byte stream up to the tool's declared output limit. Configure `call_id` and `preview_bytes` explicitly. The stream producer owns transport cleanup and deadlines; use a bounded connector runner for network reads. Oversized input is rejected, never silently sliced into a purportedly valid result. Invalid encoding, duplicate keys, nonfinite numbers, malformed JSON and schema failures produce `ResultFailure` with tool/boundary/reason fields and no raw payload in the error message.

Structured data must pass the declared schema both before and after removal of terminal-control sequences, disallowed control characters and bidi control marks. Newlines and tabs are preserved. Control-bearing keys are rejected rather than renamed. If schema validators/serializers reintroduce controls, the result fails. Text such as instructions embedded in tool output remains untrusted data; consumers must render it as escaped text and must not treat it as authority.

`NormalizedResult` preserves tenant/tool/version/call identity, the full declaration hash, original byte count, original content SHA-256, sanitization flags, detached validated data and a UTF-8-safe preview. Only the preview is truncated, with an explicit `truncated` flag and `truncation_notice`; render the notice alongside the preview. Parsed-object hashes describe their canonical JSON bytes; decoded-stream hashes describe the exact received bytes. Neither is an external provider signature.

`ToolRunner.run_result` exposes this envelope. The dict-compatible result from `run` carries provenance inside the process so direct runner-to-intent composition does not relabel sanitized data as original. Keep that carrier intact when returning it to the intent executor. It is not a wire/deserialization format or a security sandbox against arbitrary trusted Python code. Altered data, tenant/tool/version mismatch, or a different declaration hash is rejected. Ordinary JSON metadata cannot impersonate this carrier.

Intent completion stores normalized data and provenance atomically with its completion event. Replays retain both through `IntentOutcome.result` and `.metadata`, including after restart. Legacy completed intents created before migration 008 return `metadata=None`; no provenance is invented for them. Invalid output after a possible effect leaves the intent unresolved.

## Provider configuration and preflight

Pass a tenant-matching `ModelCatalog(tenant_id, tuple_of_ModelConfig)` into `create_app(..., model_catalog=catalog)`. The default catalog is empty. Configurations are immutable host inputs: stable configuration/provider IDs, model name, local/remote profile, endpoint, optional credential reference, `ModelCapabilities` and optional `PriceMetadata`. Endpoints cannot contain user information, query strings, fragments or whitespace; local endpoints must be loopback and remote endpoints HTTPS. Credentials are references (`env:NAME` or `vault:path`), never secret values. Metadata responses omit endpoints and credential references.

Tool/streaming support is explicitly true, false or unknown (`None`). Context and output limits are positive token counts or unknown. Dated pricing records use integer micro-units of the specified currency per million tokens; omitted prices remain unknown. No model-name inference, network discovery, live quote or billing estimate is performed.

- `GET /v1/models` lists configured metadata.
- `POST /v1/models/preflight` accepts `{config_id, tools, streaming, input_tokens, output_tokens}` and returns `ready`, `unsupported` or `unknown`, reason codes and a configuration hash. Tools/streaming default false; input count may be unknown; output count must be positive. Every requested feature and applicable token limit must be known and sufficient to select a model. Input plus output counts must fit the context window. These input counts are caller-provided upper bounds; the future inference adapter must calculate the full prompt and tool budget before dispatch.
- `POST /v1/tasks` optionally accepts the same object as `model`. New submissions perform local preflight before creating any task/run and persist a credential-free selection snapshot in the same transaction. Unsupported/unknown selection returns 422 with `model_unsupported`/`model_unknown`; unconfigured IDs return 404. No inference starts. Submissions without a model keep their existing contract.
- `GET /v1/runs/{id}/model` returns the original stored selection; absent or other-tenant selections return 404.

Request identity binds the client requirements, not changing provider metadata. Identical retries replay the original task and saved selection even after configuration changes/removal. Different requirements under the same request ID return 409. Only new submissions resolve the current catalog. A future model adapter must revalidate capability/configuration identity before actually invoking inference; a queued selection is not a live-provider guarantee.

## Exact expiring approvals and dispatch admission

`ApprovalStore(db, signing_key, key_id, max_ttl=86400, clock=...)` requires an explicit host-managed key of at least 32 bytes. The key is never stored in SQLite. Key rotation invalidates older signatures; there is no implicit key generation or recovery. The trusted authenticated reviewer host obtains `executor.review(actor, scope, operation_key, proposal_id)` and explicitly calls `store.issue(review, expires_at=...)`. Issuance is an internal authority boundary, not a model tool or HTTP route; an approval screen and reviewer authentication integration remain future work.

The HMAC receipt binds actor, tenant, workspace, operation key, exact proposal/run IDs, canonical arguments/declaration hashes, resource/operation context, policy version, key ID and issue/expiry times. Issuance checks the persisted proposal and nonterminal run. Immutable receipt persistence and a redacted audit entry commit together. Expiry must be after issuance and within the configured lifetime (at most one day); rollback of the clock before issuance fails closed.

Inject the store as `ToolExecutor(..., approvals=store)` and pass `approval_id` to `execute` for writes/destructive actions. The gateway requires both current scoped grants and the exact valid receipt. Missing, tampered, expired or mismatched receipts fail before reservation; the signature/bindings/clock are checked again after the final await before handler invocation and before returning any cached result. A receipt cannot authorize a second operation key. If a receipt expires after an external effect has started, that effect cannot be retracted; an already committed result may remain stored and its disclosure is denied until current approval is supplied. Expiry after reservation can leave an unresolved intent without an effect, requiring reconciliation.

After authorization auditing, a separate SQLite write transaction checks the run and records `action.dispatch_admitted` in both events and the hash-linked ledger. Its commit orders dispatch against cancellation: cancellation committed before admission blocks the handler; after admission the action is considered in flight. This does not promise rollback of an external operation. Current resources, policy and approval expiry are still checked synchronously after the admission await. Failed post-admission checks prevent the handler and conservatively leave the reserved intent unresolved.

## Hash-linked audit records

`AuditLedger.append(tenant, kind, fields)` requires an explicit `AuditField(value, Sensitivity)` for every field. Only classified scalars may be stored; confidential/secret values and known credential field names are replaced before serialization, without converting sensitive objects to strings. Invalid classification, nested unclassified values or an entry beyond 16 KiB fails the write. Classification comes from trusted host code; this is not a detector for a secret mislabeled as innocuous public text. Never pass raw model/tool output to this interface.

Entries are tenant-sequenced and hash-link the tenant, sequence, previous hash and complete redacted payload. Append-only triggers reject ordinary edits/deletes. The gateway records authorization and admission; approval issuance also writes to the ledger. Each entry shares its associated state/event transaction, so failed redaction/storage prevents that transaction from succeeding.

Capture an `Anchor` using `ledger.capture(tenant, start=1)` and retain it separately from the database. `ledger.verify(anchor)` checks the captured range under a consistent read snapshot and detects modified, reordered or missing entries, including removed tails. Appends after capture do not invalidate that segment. Hash linking is tamper evidence relative to the retained anchor, not authenticated backup: a privileged attacker who rewrites both the chain and its anchor can defeat it. Historical events are not backfilled with invented evidence.

## Internal worker interface

`LeaseStore.enqueue(tenant, run_id, step_id, kind)` records one stable step identity. Repeating the same identity is idempotent; changed work conflicts. `claim(tenant, owner, ttl)` claims queued work or recovers an expired lease under the SQLite writer lock, moves a queued run to running, increments the durable epoch and emits the claim event. TTL is greater than zero and at most 300 seconds.

`renew(lease, ttl)` and `complete(lease, succeeded_or_failed)` check the persisted owner, epoch, expiration, run revision and executable states inside the write transaction. A resumed run requires a new claim. Cancellation and terminal runs reject later completion. Completion changes the step and its event together. The single-submission path currently creates one run per task; retry-run creation and selection of a current run remain future work.

Leases protect local state commits. They cannot stop an expired process from executing arbitrary code or guarantee an external effect occurs once. A real executor must use these methods and implement operation-intent idempotency/reconciliation before effects. No model/tool execution loop is present yet.

## Storage and recovery

Migrations 001–014 are immutable, transactional and checksum checked. Add forward migrations for changes; do not drop event history or lease epochs for rollback. Test upgrades on backed-up databases. Older runtimes deliberately reject databases containing unsupported migrations.

Artifacts use tenant-scoped content-addressed files. A temporary file is fully written and fsynced, then published under the database writer lock before metadata commits. Identical complete blobs are reused, avoiding Windows replacement races. Process crashes may leave staging files or unreferenced complete blobs; no metadata points to partial bytes. Automatic garbage collection and OS power-loss testing are not implemented. No deletion on transaction rollback can remove another artifact's shared content.

Run `python scripts/test_runtime.py` for bounded local regression tests. Evidence is in planning/evidence; native UI verification and GitHub CI are separate gates.


## Structured model actions

`StructuredPlanner(proposals, max_bytes=..., max_repairs=..., repair_timeout=...)` accepts a bounded JSON object containing exactly `tool_name`, `tool_version` and `arguments`. `await planner.plan(scope, run_id, raw, repair=...)` validates the scoped registry/schema and creates an immutable proposal; it never executes or approves a tool. Duplicate keys, nonfinite values, invalid JSON/types/extras and oversized responses fail closed. Unknown tools or versions are not repairable authority failures.

Repair is optional and bounded to the explicitly configured count (0–10) and per-attempt timeout. The callback receives only a safe error code and attempt number. The host must route any repair inference through its provider/egress/budget boundaries. Failed repairs, timeout and cancellation during repair cannot plan a tool. Final proposal persistence runs in a worker thread: cancellation once that write has begun may still leave a review record, never an executed action. This is a local action parser, not a live model adapter.

## Run budget admission

`BudgetStore.configure(tenant, run_id, BudgetLimits(tokens, tool_steps, wall_seconds, max_cost_microunits, currency, allow_unpriced))` fixes a run's limits and persisted deadline. Repeating the same configuration preserves the original deadline; changing it conflicts. All counts use nonnegative safe integers. `reserve(..., action_id, ActionEstimate(...))` atomically reserves an upper bound before work; concurrent reservations cannot overspend. The same key/estimate returns the original admission; changed estimates conflict. Reservations are never automatically refunded after failure, timeout, cancellation or an unknown outcome.

`await store.execute(..., operation)` provides bounded admission for a trusted async model/adapter call. Repeated action IDs do not execute again and require outcome reconciliation. Adapters must enforce the declared input/output token bounds; the store cannot stop a dishonest transport from exceeding its estimate. Limits are admission estimates, not observed usage or bills. Read-only `usage` reports reservations.

`ActionEstimate.inference(input_tokens, output_tokens, price)` computes an integer ceiling from the configured dated per-million-token prices. Missing prices stay unknown. If `allow_unpriced` is false, unknown price blocks admission. If explicitly true, token/step/time limits govern unpriced calls and only the known-price subtotal is capped; `estimated_cost_microunits` is `None` once any unpriced call is reserved. This opt-in does not promise a total monetary ceiling. Currency mismatches fail.

Inject `budgets=store` into `ToolExecutor` to require a configured budget and charge each first tool dispatch atomically with admission. Each `ToolBinding` may supply a trusted synchronous `budget(arguments)` estimate (at least one tool step); without one, tool cost is unknown, never assumed free. Successful intent replay does not charge another step. Deadline and authorization checks run inside the scheduled bounded operation immediately before the handler. Persisted wall-clock rollback before run-budget creation fails closed. No automatic runtime loop or provider billing integration is added.

## Data egress

`EgressGateway` is a host-only outgoing-data boundary with fixed `Destination`/async transport bindings, a current `EgressPolicy`, an explicit byte limit and timeout. `send(actor, destination_id, fields, artifact_ids)` selects only allowlisted fields, requires a `ClassifiedField` for every selected field, and resolves exact tenant-owned artifact IDs through `ArtifactStore`. `ArtifactClassifications.classify` persists a known classification immutably with an audit record; a different classification requires a new artifact record. Unknown classifications, unauthorized attachments or corrupted artifact bytes block transmission.

Grants bind the exact actor/workspace, destination ID **and endpoint**, field names, artifact IDs and classifications. Restricted data cannot go to a remote destination even if a grant lists that classification. Every fallback must call the gateway again for its own registered destination. Payload/attachment metadata and bytes share the configured outgoing limit. Policy is checked again inside the scheduled transport call after auditing. Audit records contain identities, not transmitted content.

Classifications and adapters are trusted host inputs; this is not automatic secret detection or a Python/network sandbox. Transports must use the bound endpoint, enforce TLS/peer validation and reject redirects; they must not forward credentials across destinations. This batch uses fixture transports and makes no external transmissions. No public grant-creation or classification endpoint is exposed.

## Connector declarations and conformance

`packages/connectors/manifest.py` defines strict versioned connector/operation records. Protocol version 1, unique operations/tools, semantic versions, known effect classes and nonempty explicit capabilities are required. `enable(manifest, tools)` validates the complete implemented tool set, versions, effects and capabilities before returning an isolated registry. Enabling a declaration does not grant execution permission or install credentials.

`packages/connectors/tests/contract_suite.py::check_adapter` runs the same success, authentication/permanent/transient/timeout/unknown-error, invalid-input and denied-capability checks for each supplied adapter fixture. Provide its declared tool, scope, valid arguments, expected result, named-scenario factory and timeout. The factory should wire the real adapter to controlled local transport fixtures. The suite checks raw adapter failure classifications before conservative write-error remapping, retry counts, schema/byte limits and no dispatch on denied input. It rejects malformed or unbounded successful output. It does not certify real credentials, transport security, external idempotency or business correctness; those need connector-specific tests.

## Workspace backup and recovery quarantine

`WorkspaceBackups(db, max_bytes=..., max_artifacts=..., timeout=...)` is a trusted host filesystem API. `create(absolute_new_directory)` captures SQLite and all referenced content-addressed blobs while holding the database writer lock, verifies metadata/hashes, and publishes a self-contained database plus versioned manifest. Unreferenced staging/orphan blobs and credentials outside SQLite are not exported. Size, artifact-record count and elapsed-time limits are explicit. This may temporarily block workspace writers; do not run it on the UI/event-loop thread.

`restore(snapshot_directory, absolute_new_directory)` verifies manifest/checksums, supported migration prefix, actual tables/indexes/triggers, foreign keys, core payload projections and all referenced artifact hashes. It rejects corrupt/newer backups, active journals, links/junctions and existing destinations. Migration discovery supports both source and installed-wheel layouts. Validation and upgrades happen in a private sibling staging directory before publishing the new workspace. Restore never replaces the active workspace.

**Every restored workspace is read-only pending reconciliation.** A snapshot may predate an external action that completed in the original workspace; restoring its approvals and operation history must not authorize that action again. Migration 014 records a durable recovery flag, and normal application write transactions—including intents, approvals, budgets and worker leases—reject with `recovery_required`. Reads remain available. Authenticated `GET /v1/workspace/recovery` reports the flag and reason; attempted API writes return 409. Restart preserves quarantine. There is intentionally no automatic reactivation endpoint; reviewed reconciliation/reactivation tooling remains future work. The migration/restore transaction override is trusted host administration, never model/API authority.

Snapshot hashes detect corruption, not forgery by an attacker who can replace both data and manifest. Keep source/destination parent directories host-controlled. This is not protection against arbitrary privileged filesystem races, disk loss, power-loss during directory publication, or an adapter bypassing application transaction boundaries.


## Native desktop connection

The desktop owns the Go platform sidecar, which launches `python -u -m veya.desktop` from its trusted runtime resource directory. Set `VEYA_PYTHON` in the host environment to select the supported interpreter. Python dependencies remain an explicit prerequisite; no installer is downloaded at startup. A versioned bootstrap with absolute workspace path and an ephemeral credential travels through inherited stdin. The runtime binds an OS-selected IPv4 loopback port, emits readiness only after startup, and exits on parent-pipe EOF. The host validates protocol and authenticated health, serializes lifecycle operations, and terminates only its owned child after a bounded shutdown timeout. Safe diagnostics stay in the native application data directory.

Only the local main window has the three declared commands: `runtime_health`, `runtime_restart` and `workspace_call`. Workspace operations are a fixed allowlist for tasks, documents, results, reviewed approvals, tested connections and explicit read-only execution. UI content cannot supply arbitrary worker paths, headers, tenants, filesystem paths or executable arguments. Configured provider endpoints have a separate destination policy; they do not select runtime addresses. Native requests add the credential; Angular never receives it. Runtime HTTP still rejects missing credentials and all supplied browser Origin headers. This controls native capabilities, not malicious code already running as the OS user.

Authenticated additions: `GET /v1/health` reports protocol1 and execution availability; `GET /v1/tasks/{id}/latest-run` returns the latest tenant-owned run; `GET /v1/runs/{id}/event-page?after=<cursor>` returns up to25 events, the last cursor and a has_more flag. The JSON page shares the persisted log and validation of SSE. Native responses are capped at2MiB and deadlines; ten recent tasks fit even at maximum JSON escaping. The UI retains at most500 activity rows and resumes from its last validated cursor after interruption. Partial events never set a task to completed.

Draft text and stable request identity are versioned in local WebView storage before dispatch. Duplicate clicks share one request; unknown outcomes retry the same immutable payload. Definitive validation rejection allows correction. The native application identifier and old relay-demo-v1 storage remain unchanged, preserving prototype data separately from real tasks. Read-only execution and attachment operations are described below; external business writes are not enabled in the agent.
## Review and accounting additions

`GET /v1/approvals?after=0&limit=50` returns a bounded page of pending, unexpired requests. `GET /v1/approvals/{id}` returns the exact proposed arguments and policy version. `POST /v1/approvals/{id}/decision` accepts `{revision, decision: "approve"|"reject", note}`. One decision advances the revision; competing, stale or expired decisions return conflict. A lost response is reconciled by fetching the request rather than issuing a second decision.

These routes require the ordinary runtime credential plus a separately configured `X-Veya-Reviewer-Token`. The app factory takes an explicit scoped `ApprovalInbox` and a distinct reviewer token; default desktop/model sessions have no review authority. The trusted host enqueues immutable proposal reviews. Expired pending reviews can be superseded without changing the business operation key; old requests remain readable and cannot be approved. A decision only issues a receipt: execution remains a separate gateway operation.

`ApprovalStore.revoke` durably revokes a receipt. The gateway rechecks current policy, resources, expiry and revocation immediately before dispatch and before returning cached results. Revocation cannot retract an effect already in flight. Unresolved external outcomes never permit automatic redispatch.

`GET /v1/runs/{run_id}/usage` returns separate provider-reported and estimated cost totals per currency, the number of calls with unknown/incomplete accounting, and a completeness flag. `GET /v1/runs/{run_id}/usage/calls?after=0&limit=50` exposes paginated call evidence with the captured pricing date/version. Amounts are exact decimal strings. Missing usage or prices remain unknown; estimates never substitute for provider reports. Trusted inference adapters must call `UsageStore.begin` before dispatch and `finish` after the response; these accounting endpoints do not themselves dispatch inference. The bounded agent currently enforces conservative reservations; per-call provider billing reconciliation remains separate integration work.

Tool events retain a versioned `span` with proposal, operation and attempt identifiers across proposal, approval, dispatch admission, completion and retry. A started span denotes an admitted attempt, not proof an external effect occurred. Unknown outcomes are explicit; replay does not add another success. Classified attributes are redacted before entering the durable event stream. Existing event-page/SSE endpoints deliver these records.

## Tested connections and read-only execution

Authenticated runtime routes: `GET /v1/connections`; `POST /v1/connections/check` with `{config, consent}`; `POST /v1/connections/activate` with `{fingerprints}`; `POST /v1/connections/credential` with `{reference, secret}`. Credentials are write-only Windows Credential Manager entries scoped to the workspace and tenant. No read-credential operation exists. Local adapters accept numeric loopback `/v1` endpoints without credentials; hosted adapters accept exactly `https://api.openai.com/v1`. Requests disable redirects and environment proxies, bound input/output sizes and require explicit hosted consent. Streaming output is accepted only with a valid terminal completion and DONE marker.

`POST /v1/runs/{id}/execute` accepts `{expected_selection, allow_remote}`. Selection mismatch, prohibited remote use, insufficient context, and invalid run state reject admission. The private worker snapshots tested configs and starts a bounded read-only agent. The task must explicitly permit internal data for every displayed hosted provider; restricted data cannot fall back remotely. Source access is revalidated before each dispatch/fallback and publication. `POST /v1/runs/{id}/cancel` fences late artifacts. Migration 022 records provider snapshots and agent jobs; restart marks interrupted jobs failed. Duplicate start does not create a second job.

Go exposes `connections`, `check_connection`, `activate_connection`, `save_credential`, `execute_run`, `cancel_run`, and `document_chunks` through the existing authenticated command boundary. Payloads cannot select arbitrary runtime paths. `GET /v1/documents/{id}/chunks?after=0` returns bounded, version-linked text chunks with original source offsets; grants remain authoritative.

EML imports retain sender, zoned date, body and safe attachments under one immutable message grant. Nested messages, malformed encodings, traversal filenames, unsupported attachments and expanded limits fail closed. Finance value objects, effective-dated policy resolution, duplicate candidates and fixture ERP operations are host libraries with synthetic integration tests. The fixture ERP accepts only explicitly synthetic tenants and binds writes to the existing approval/idempotency gateway; it is not exposed as an agent write tool or a real ERP integration. Sanitized contract cassettes contain explicitly public fields and are replayed offline.


## Engineering evidence and data review

The authenticated Go workspace allowlist adds `list_evaluations`, `get_evaluation`, `list_trajectories`, `get_trajectory` and `review_trajectory`. The private runtime exposes `/v1/research/evaluations` and `/v1/research/trajectories`, with `?after=0` sequence pagination and `/{id}` details. Lists return at most 25 records. Report plans retain every declared repetition, including missing, abandoned and failed runs. Token/cost values may be unknown; they are not replaced with zero.

`POST /v1/research/trajectories/{id}/review` accepts `{revision, fingerprint, decision, tags, note}`. Decisions are `approved` or `rejected`. The host supplies the personal workspace reviewer identity; callers cannot choose a reviewer or tenant. Review history is append-only and limited to 100 decisions per trace version. This research review does not approve business tool execution. Approval requires current source authorization, and corpus export rechecks it under the workspace writer lock. The original trace remains immutable.

Research ingestion and source permission changes are local host operations, deliberately absent from model and renderer capabilities. Run `python scripts/import_research.py --help` to import an explicitly selected validated record or allow/revoke an exact source ID. Use `python scripts/run_research.py --help` for resumable paired local Ollama evaluations, experiment bundle verification and GPU preflight. A batch plan supplies `specs` keyed by `baseline` and `candidate`, a pinned `split`, task-ID-to-path `snapshots`, and task-ID-to-`{instruction, expected_state}` `inputs`. Snapshots resolve relative to the plan file. Reusing the workspace and evaluation ID resumes unfinished repetitions; a changed plan is rejected.

Experiment bundles contain pinned configurations, split assignments, a bounded public result projection and a code hash. Private source bytes are excluded by default. Replaying requires the same authorized source snapshots and pinned inputs. Review corpus export scrubs classified fields and blocks unclassified fields, rejected/unreviewed records, held-out neighbors and revoked sources. This corpus is not a tokenizer-specific training dataset. No endpoint or command here deploys a model or starts training.
